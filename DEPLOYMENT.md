# R19 device setup and recovery

For a working board, start the dashboard and verify the current release. Use [bench/RELEASE_HASHES.json](bench/RELEASE_HASHES.json) and the [install receipt](bench/INSTALL_RECEIPT.json). The R19 firmware fingerprint begins `438ec766` and the config fingerprint begins `ad664dec`. They identify the board software used for the paired power comparison. A different board may have an earlier release installed.

The repository includes the verified staged release, boot files, model assets, MicroPython sources and compiled modules. The measured board installation reused model assets under `/flash/releases/haar-box-r3-20261110`. A separate board may lack that directory. A self-contained deployment uses the included model files and creates its own model paths, so its resulting config and firmware fingerprints can differ from the measured board. Record the new receipt and do a USB smoke test before using it for the demo.

Run `sh SETUP_MAC.command` on Mac or `SETUP_WINDOWS.cmd` on Windows from the repository root. Both install `mpremote==1.29.0` in the app's local environment. Windows setup uses online installation when the optional wheel folder is absent. The deploy tool also discovers the Windows environment without activation.

For a needed install or recovery, use a compatible OpenMV Nicla with a readable `/flash/main.py`. Stop and close the dashboard and any serial clients. Discover the current device port with `python -m serial.tools.list_ports` using the environment's Python. On Mac that executable is `FaceRecognition/.venv-nicla/bin/python`. On Windows it is `FaceRecognition\.venv-nicla-windows\Scripts\python.exe`. Use the same executable to run `FaceRecognition/tools/deploy_nicla_runtime.py --help` and the installation command.

For a self-contained R19-family installation, run the deploy tool with `--port <actual-port> --release-id <new-unused-id> --detector-backend gray_haar_box --haar-distance-roi --haar-local-contrast --haar-walking-zoom --haar-responsive --haar-close-face --haar-fast-live --compact --enable-battery-sightings --keep-watchdog-fed`. Let the tool check free space, stage and verify hashes, and preserve the active release for rollback before switching. Use the installed release as the starting point whenever it already works. Avoid Finder or Explorer file copies to the board's flash.

Replace both placeholders with the detected port and a fresh release ID before running. These options select the evaluated Haar detector, responsive camera pipeline, and on-board photo queue. The Haar profile disables automatic known-person acceptance. The generic defaults in `firmware/runtime_config.json` describe the earlier FOMO configuration. Preserve the source files, compiled modules, model files, and their manifests together when updating the repository. The deploy tool checks these hashes before installation and reads every installed file back before activation. Installation receipts and backups are written under `work/project-finish-v4/deployments/backups/`.

After activation, reconnect, confirm the release hashes and run the face and blank checks in [the rehearsal checklist](work/project-research-v5/final-readiness-2026-11-12/FINAL_READINESS.md). This handoff verifies the artifacts offline. The original R19 install and live bench evidence are recorded in the included receipts.
